EBM System — مشروع ويب جديد من الصفر
====================================
الملفات:
index.html واجهة النظام
style.css التصميم المتجاوب للموبايل والكمبيوتر
app.js إدارة الماكينات والبلاغات وسجل الصيانة
firebase-config.js إعدادات مشروع Firebase الجديد emtr-10091 ومفتاح VAPID العام
firebase-messaging-sw.js ملف تمهيدي لخدمة الإشعارات
manifest.json إعدادات الموقع

التشغيل:
1) فك الضغط ثم ارفع المجلد إلى استضافة HTTPS مثل GitHub Pages أو Firebase Hosting. لا تفتح index.html مباشرة من مدير الملفات.
2) أنشئ Realtime Database في مشروع Firebase emtr-10091.
3) انسخ رابط قاعدة البيانات الفعلي إلى databaseURL داخل firebase-config.js بدل PASTE_REALTIME_DATABASE_URL_HERE.
4) قبل استخدامه على بيانات مصنع حقيقية، اضبط قواعد وصول آمنة وتسجيل دخول وصلاحيات.
5) حتى قبل ربط Firebase، تقدر تجرب النظام محليًا في نفس المتصفح؛ البيانات لا تنتقل بين الأجهزة إلا بعد ضبط قاعدة البيانات.
ملاحظات:
- هذه نسخة تأسيسية وليست نظامًا جاهزًا للاستخدام الإنتاجي: تسجيل الدخول والصلاحيات غير مضافة بعد.
- تنبيهات المتصفح تتطلب موافقة المستخدم ودعم المتصفح.
- إشعارات الخلفية بعد إغلاق الموقع تحتاج Firebase Cloud Messaging وخدمة إرسال موثوقة (مثل Cloud Functions). لم يتم نشرها على حسابك.
- لا تضع مفاتيح Service Account السرية في ملفات الويب.

تحديث إضافي:
- زر «تفعيل التنبيهات والصوت» يطلب إذن إشعارات المتصفح ويجرب نغمة صوتية.
- عند تسجيل بلاغ جديد داخل الموقع، يتم تشغيل تنبيه صوتي.
- عند إضافة ماكينة يوجد حقل سيريال وزر تصوير لقراءة باركود/QR بالكاميرا إذا كان المتصفح يدعم BarcodeDetector.
- قراءة الكاميرا تحتاج HTTPS أو localhost وإذن الكاميرا. إذا كان السيريال مكتوبًا فقط وليس باركودًا/QR، أدخله يدويًا.
- الصوت يعمل عندما تكون صفحة الموقع مفتوحة. بعد إغلاق الموقع، الصوت يعتمد على إشعارات النظام/المتصفح؛ إشعارات الخلفية الحقيقية تحتاج إعداد Firebase Cloud Messaging وإرسال من خادم موثوق، وهذا لم يتم تفعيله تلقائيًا.


ميزة قراءة السيريال المكتوب بالكاميرا (OCR): افتح إضافة ماكينة > تصوير > بدء الكاميرا > وجّه الكاميرا للسيريال المكتوب بوضوح > تصوير وقراءة السيريال. تستخدم قراءة النصوص Tesseract.js من CDN، لذلك يلزم اتصال بالإنترنت لتحميل المكتبة وبيانات اللغة، ويجب مراجعة الرقم المقروء قبل حفظ الماكينة. تعمل الكاميرا فقط عبر HTTPS أو localhost وبعد منح إذن الكاميرا.


تحسين قراءة السيريال: تم تضييق منطقة القراءة إلى منتصف الصورة، وتكبيرها، وتحويلها لتباين أعلى، واستخدام وضع قراءة سطر واحد مع حصر الأحرف المسموح بها. وجّه الكاميرا بحيث يظهر سطر السيريال وحده في المنتصف. راجع الرقم في خانة السيريال قبل حفظ الماكينة؛ OCR قد يخطئ في الحروف المتشابهة.

تحديث قراءة السيريال (FIXED4):
- جرّب توجيه السيريال وحده إلى منتصف صورة الكاميرا، بحيث لا تظهر كتابة أخرى في المنطقة الوسطى.
- يحلل النظام 3 نسخ محسنة من الصورة ويقبل تلقائيًا فقط نمط السيريال التجريبي المكون من 6 أرقام + حرفين + 4 أرقام، مثل 021153ND0186.
- إذا لم يطابق النص النمط، فلن يملأ الحقل تلقائيًا حتى لا يسجل كتابة عشوائية من جسم الماكينة. اكتب السيريال يدويًا أو أعد التصوير عن قرب.


إصلاح مشاركة البيانات بين الأجهزة (SYNC FIX):
1) افتح Firebase Console ثم المشروع emtr-10091 ثم Realtime Database. أنشئ قاعدة بيانات إذا لم تكن موجودة.
2) انسخ رابط قاعدة البيانات كما يظهر في صفحة Realtime Database (يبدأ بـ https:// وينتهي غالبًا بـ firebasedatabase.app أو firebaseio.com).
3) افتح firebase-config.js وضع الرابط بدل PASTE_REALTIME_DATABASE_URL_HERE مع إبقاء الرابط بين علامتي اقتباس.
4) ارفع كل ملفات المجلد إلى الاستضافة نفسها HTTPS، ثم افتح الموقع على الجهازين واعمل تحديثًا للصفحة.
5) يجب أن تظهر عبارة «متصل — البيانات مشتركة». إذا ظهرت «رفض الوصول»، فالمشكلة في قواعد الوصول. لا تستخدم قواعد عامة مفتوحة على بيانات المصنع في الاستخدام الحقيقي؛ أضف Firebase Authentication وقواعد آمنة.
6) أول مرة فقط، إذا كانت قاعدة البيانات السحابية فارغة وفي الجهاز الأول بيانات محلية، سيحاول النظام رفعها. إذا كانت قاعدة البيانات تحتوي بيانات، فستكون بيانات السحابة هي المعتمدة.
مهم: الرابط الحقيقي غير موجود في ملفات المشروع الحالية، لذلك لا يمكن تفعيل المزامنة نهائيًا من دون نسخه من Firebase Console.
